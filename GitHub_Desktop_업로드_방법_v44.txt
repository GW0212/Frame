FRAME! v44 — 파일 종류별 적용 안내 (먼저 읽어주세요)
===================================================

방법 A. 기존 FRAME! v43이 이미 GitHub Desktop 로컬 저장소에 있는 경우 [추천]
  파일: FRAME_v44_신규53편_GitHubDesktop업데이트.zip
  1) 업데이트 ZIP을 '새로운 빈 임시 폴더'에 압축 해제합니다.
  2) GitHub Desktop > Repository > Show in Explorer 로 기존 FRAME 저장소를 엽니다.
  3) '기존 movies 폴더는 삭제하지 않습니다.'
  4) 압축 해제한 ZIP의 movies/한국 영화 및 movies/외국 영화 안에 있는
     '신규 영화 폴더들'을 기존 저장소의 같은 이름의 카테고리 폴더에 복사합니다.
     movies/manifest.json은 기존 파일을 덮어씁니다.
  5) 압축 해제한 index.html, catalog-v27.js, poster-seed-v22.js,
     tools/verify_images.py, tools/build_manifest.py 등 나머지 파일도
     같은 상대 경로로 복사하고, 기존 파일이 있으면 덮어씁니다.
  6) GitHub Desktop Changes 탭에서 변경 목록을 확인하고 아래 Commit/Push를 진행합니다.

방법 B. 전체 웹사이트를 새로 구성하거나 기존 movies를 완전히 교체할 경우
  파일 2개: FRAME_v44_전체본_A_웹사이트_한국영화.zip
             FRAME_v44_전체본_B_외국영화.zip
  1) 두 ZIP을 동일한 '새 빈 폴더'에 압축 해제합니다.
  2) index.html, movies/한국 영화, movies/외국 영화, movies/manifest.json
     등의 구조가 완성됐는지 확인합니다.
  3) GitHub Desktop의 기존 저장소 폴더에서 .git은 유지하고,
     기존 movies 폴더는 백업 후 삭제한 다음 합쳐진 새 movies 폴더로 교체합니다.
  4) 나머지 파일도 기존 저장소에 덮어쓴 뒤 Commit/Push합니다.

[중요] '신규53편 업데이트 ZIP'은 기존 movies를 통째로 대체하는 용도가 아닙니다!
기존 영화가 빠지지 않게 방법 A/B를 구분하여 진행하세요.

FRAME! v44 — GitHub Desktop으로 기존 저장소 업데이트하기
=================================================

준비: 다운로드한 FRAME! v44 ZIP을 새 빈 폴더에 압축 해제하세요.
압축 해제하면 index.html, movies, assets 등이 최상위에 보여야 합니다.

[1] GitHub Desktop 실행
- File > Clone repository 를 이미 한 경우 다시 Clone하지 마세요.
- Current Repository에서 기존 FRAME 저장소를 선택합니다.
- 아직 Clone하지 않았다면 File > Clone repository > URL 에
  https://github.com/GW0212/Frame.git 입력 후 Clone 합니다.
- Clone 은 기존 웹사이트 주소를 변경하는 과정이 아닙니다.

[2] GitHub Desktop에서 로컬 저장소 열기
- Repository > Show in Explorer (탐색기에서 표시)를 클릭하세요.
- 열린 폴더에는 .git 및 index.html, movies 등이 있습니다.
- .git 폴더는 절대 삭제하지 마세요.

[3] 프로젝트 파일 교체
- 현재 로컬 저장소에서 기존 movies 폴더를 삭제합니다.
  (영화 데이터 보관이 필요하면 먼저 다른 곳에 백업하세요.)
- v44 ZIP에서 압축 해제한 movies 폴더를 복사합니다.
- 나머지 웹사이트 파일(index.html, app.js, catalog-v27.js,
  poster-seed-v22.js, CSS, assets, tools, .github 등)도 저장소로 복사하여 덮어씁니다.
- ZIP 파일 자체를 GitHub 저장소에 넣는 것이 아니라
  ZIP 내부의 파일과 폴더를 저장소 루트에 넣어야 합니다.

[4] GitHub Desktop에서 변경사항 확인
- GitHub Desktop의 Changes 탭에서 새 영화 파일, 갱신된 목록 파일,
  삭제/이동된 파일이 올바르게 표시되는지 확인하세요.
- Commit to main 이 비활성화되어 있으면 Summary(required)에
  예: FRAME v44 신규 영화 및 이미지 업데이트
  처럼 변경 설명을 입력하세요. 체크된 변경 파일이 없으면 커밋할 수 없습니다.

[5] Commit / Push
- Commit to main 클릭: PC의 로컬 Git 기록에 변경 저장
- 상단 Push origin 클릭: GitHub 온라인 저장소에 업로드
- Fetch origin 은 온라인 변경 확인일 뿐, 업로드는 아닙니다.
- Push origin 중 오류가 나면 메시지를 확인하세요.

[6] 배포 확인
- GitHub의 해당 저장소 > Actions에서 배포 workflow가 성공했는지 확인
- GitHub Pages 웹사이트를 새로고침합니다.
- 난이도 선택 화면에서 전체(n개)가 아래 숫자와 일치하는지 확인
- 포스터와 장면을 몇 개 플레이하여 경로 누락이 없는지 확인

[주의]
- 기존 .git 폴더를 지우면 GitHub Desktop 연결이 끊깁니다.
- 기존 movies 폴더를 부분 덮어쓰기하면 이전에 삭제됐어야 할
  WebP가 남을 수 있으므로 완전히 교체하는 것이 좋습니다.
- GitHub Desktop은 PC 로컬 복사본을 사용하는 방식입니다.
- PC 로컬 파일은 Push 이후에도 남아 있습니다.
